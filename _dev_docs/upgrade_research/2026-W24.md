## Tier 1 — drop-in supersessions (ship soon)

These have available weights/node packs, no workflow rewrites required, and clear quality or efficiency gains.

### 1 · HyperSwap ONNX → `build_faceswap`, `build_video_reactor`

- **What:** `hyperswap_1a/1b/1c_256.onnx` from FaceFusion Labs — direct replacement for `inswapper_128.onnx`
- **Why now:** Already supported in ComfyUI-ReActor v0.6.2 (2026-04-25). Higher identity accuracy, three quality tiers.
- **Action:** Update ReActor node pack → swap `swap_model` default from `inswapper_128.onnx` to `hyperswap_1c_256.onnx`
- **VRAM:** No change (ONNX inference)
- **Source:** https://github.com/Gourieff/ComfyUI-ReActor

### 2 · ComfyUI-ReActor v0.6.2 node pack → `build_faceswap`, `build_video_reactor`

- **What:** New `ReActorFaceBoost` node; targeted per-face restore; `FACE_MODEL_NAME` output; 10× image analyser speedup for video
- **Action:** `pip install -U ComfyUI-ReActor` (or Git pull)
- **Source:** https://github.com/Gourieff/ComfyUI-ReActor

### 3 · BiRefNet_dynamic → `build_rembg_birefnet`

- **What:** Single model handling 256–2304 px input vs fixed-resolution `BiRefNet-general`; SDPA attention (Sept 2025) speeds inference
- **Action:** Change model ID from `ZhengPeng7/BiRefNet` to `ZhengPeng7/BiRefNet_dynamic` — identical API
- **VRAM:** Negligible change
- **Source:** https://huggingface.co/ZhengPeng7/BiRefNet

### 4 · Marigold-Normals v1.1 → `build_normal_map`

- **What:** Current SOTA diffusion surface-normal estimator; 1–4 denoising steps; outperforms all prior diffusion normal methods
- **Action:** Swap checkpoint to `prs-eth/marigold-normals-v1-1` — same diffusers pipeline
- **VRAM:** No change
- **Source:** https://huggingface.co/prs-eth/marigold-normals-v1-1

### 5 · SeedVR2 v2.5 → `build_seedv2r`

- **What:** 60% VRAM reduction, 2–3× faster (torch compile + flash attention), GGUF Q4/Q8, improved colour correction, stream processing for unlimited-length video
- **Note:** `build_seedv2r` node changes are lower risk than `build_seedvr2_video_upscale` (see Tier 3 for that one)
- **Source:** https://github.com/numz/ComfyUI-SeedVR2_VideoUpscaler

### 6 · FLUX.2-small-decoder → all Klein-family builders

- **What:** Drop-in faster VAE decoder for all FLUX.2 pipelines; 203 K downloads; reduces decode time
- **Action:** Wire `FLUX.2-small-decoder` as the default decoder in `load_model_stack` for Klein presets
- **VRAM:** Slightly lower
- **Source:** https://huggingface.co/black-forest-labs/FLUX.2-small-decoder

### 7 · Klein 9B LoRA collection (released 2026-06-05 to 2026-06-08) → Klein-family builders

- **What:** New style/subject/anime LoRAs for `FLUX.2-klein-base-9B` released this week
  - `msrcam/Flux.2_Klein_9B_LoRas` (updated 2026-06-07)
  - `neonforestmist/storybook-anime-flux-2-klein-9B-lora` (2026-06-05)
  - `ebadhussain20/flux2-klein-fashion-lora` (2026-06-08, 0 DL — very new)
- **Action:** Add to Spellcaster LoRA catalogue; curated list can expand `build_klein_*` style options

### 8 · NVIDIA RTX VSR ComfyUI node → `build_video_upscale`, `build_upscale`

- **What:** Official `Comfy-Org/Nvidia_RTX_Nodes_ComfyUI` node; uses dedicated Tensor Core hardware on RTX GPUs; 30× faster than ESRGAN per Comfy blog (GDC 2026)
- **Caveat:** Temporal consistency ≠ per-frame ESRGAN sharpness — evaluate per use case
- **Action:** Add as optional `upscaler_type: "rtx_vsr"` variant in both builders
- **Source:** https://github.com/Comfy-Org/Nvidia_RTX_Nodes_ComfyUI

## Tier 2 — additive new builders (needs node-pack install or new architecture evaluation)

### 1 · Ideogram 4.0 → `build_txt2img` (text-heavy / layout-precise variant)

- **Architecture:** 9.3 B DiT (flow matching, built from scratch — not Flux/SD)
- **Strengths:** 0.97 X-Omni OCR score (multilingual text rendering), JSON layout/bounding-box control, native 2 K
- **Licence:** Ideogram 4 Non-Commercial — no commercial use without agreement
- **VRAM:** NF4/GGUF quants available; NF4 runs on ~12–16 GB
- **ComfyUI:** Day-0 native support via `Comfy-Org/Ideogram-4` package
- **Action:** Prototype `build_ideogram4_txt2img`; wire separately from SDXL/Flux path
- **Source:** https://huggingface.co/ideogram-ai/ideogram-4-fp8

### 2 · HunyuanVideo-1.5 → `build_hunyuan_video`

- **Architecture:** 8.3 B (down from 13 B+); SSTA (Selective & Sliding Tile Attention) for 75% KV reduction
- **Perf:** 75% faster distilled 480p I2V; 8–12 steps; supports 1080p T2V + I2V
- **VRAM:** FP8 fits 16 GB; NVFP4 ModelOpt variant for RTX 50-series
- **ComfyUI:** Repackaged at `3loso3/HunyuanVideo_1.5_repackaged` (Apr 2026)
- **Action:** Replace `HunyuanVideo` checkpoint default in `build_hunyuan_video` — evaluate I2V pipeline API changes
- **Source:** https://huggingface.co/tencent/HunyuanVideo-1.5

### 3 · DreamID-V (ByteDance) → `build_faceswap_mtb` (video face-swap path)

- **Architecture:** Diffusion Transformer (DiT) on Wan2.1-1.3B; SOTA on IDBench-V
- **Requirement:** 16 GB VRAM min; video-only (not still-image drop-in for MTB)
- **ComfyUI:** `ComfyUI_JR_DreamID-V` v0.4.0 (Feb 2026); Apache-2.0
- **Action:** Add as optional video-mode path in `build_faceswap_mtb` or new `build_dreamidv_faceswap`
- **Source:** https://github.com/bytedance/DreamID-V

### 4 · OSDFace → `build_face_restore`, `build_photo_restore`

- **Architecture:** One-step diffusion blind face restoration; VRE + GAN discriminator for identity consistency
- **Perf:** ~0.1 s at 512 px; better FID/LPIPS than CodeFormer; CVPR 2025
- **Gap:** No native ComfyUI node — needs wrapper analogous to CodeFormer node
- **Action:** Write a minimal ComfyUI node wrapping the OSDFace inference script; replace CodeFormer default
- **Source:** https://github.com/jkwang28/OSDFace

### 5 · Depth Anything 3 (DA3-LARGE-1.1) → `build_depth_map_v3`

- **Architecture:** Plain ViT / DINOv2 encoder; unified mono + stereo + multi-view; depth-ray prediction
- **Perf:** ICLR 2026; 35.7% camera-pose gain over DA2; 23.6% geometric accuracy gain on DA3-BENCH
- **Gap:** API surface changed from DA2 — existing DepthAnythingV3 ComfyUI node may need an update
- **Action:** Test with `depth-anything/DA3-LARGE-1.1`; file node-compatibility issue if API differs
- **Source:** https://huggingface.co/depth-anything/DA3-LARGE-1.1

### 6 · Hunyuan3D 2.5 LATTICE → `build_hunyuan_3d_mesh`, `build_hunyuan_3d_textured`

- **Architecture:** LATTICE 10 B shape foundation model; PBR multi-view texture synthesis; paper arXiv 2506.16504 (ICCV 2025)
- **Open-weight:** `tencent/Hunyuan3D-2` on HF updated to v2.5
- **PBR:** New capability — current pipeline has no PBR output
- **Action:** Evaluate LATTICE weights against existing Hunyuan3D 2.x ComfyUI nodes; plan `build_hunyuan_3d_textured` PBR output path
- **Source:** https://huggingface.co/tencent/Hunyuan3D-2

### 7 · LTX-Video 0.9.8-13B-distilled → `build_ltx_video` (stepping stone)

- **Why:** Current backbone is v0.9.7; 0.9.8-13B-distilled is confirmed on HF, 2.1 K downloads; better quality/speed; stepping stone to LTX-2.3
- **VRAM:** FP8 fits 16 GB
- **Action:** Update `build_ltx_video` to 0.9.8-13B-distilled before tackling full 2.3 upgrade
- **Source:** https://huggingface.co/Lightricks/LTX-Video-0.9.8-13B-distilled
