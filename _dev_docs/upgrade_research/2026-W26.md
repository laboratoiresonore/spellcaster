## Tier 1 — drop-in supersessions (ship soon)

Confirmed upgrades with available (or near-available) weights that directly replace the current backbone and fit within the 16 GB budget (or fit with quantization).

### 1. Hunyuan3D 2.5 → `build_hunyuan_3d_mesh` + `build_hunyuan_3d_textured`

- **Paper:** https://hf.co/papers/2506.16504 (Jun 19) + companion PBR release https://hf.co/papers/2506.15442 (Jun 18)
- **What changed:** LATTICE shape foundation model (up to 10B params) + production-grade PBR texture synthesis. Substantially outperforms 2.0/2.1 in geometry fidelity and texture quality.
- **Risk:** Medium — 10B variant likely exceeds 16 GB at fp16. Confirm smaller variant or quantized checkpoint before deploying.
- **Action:** Find 16 GB-compatible Hunyuan3D 2.5 checkpoint on HF (smaller variant or INT8/NF4 quant). Update `build_hunyuan_3d_mesh` and `build_hunyuan_3d_textured` weight paths. Requires local install check for updated ComfyUI Hunyuan3D node.

### 2. Qwen-Image-2.0 → `build_qwen_edit`

- **Paper:** https://hf.co/papers/2605.10730 (May 11, 2026)
- **What changed:** New architecture — Qwen3-VL as conditional encoder + Multimodal Diffusion Transformer for joint generation and editing. Major upgrade over the current Qwen image editing model.
- **Risk:** Medium — full model VRAM unspecified; quantization likely needed for 16 GB.
- **Action:** Locate Qwen-Image-2.0 weights on HF. Evaluate INT4/INT8 quant. Update `build_qwen_edit` `unet_name`, `clip_name`, `vae_name` defaults.

### 3. SeedVR2 → `build_seedv2r`

- **Paper:** https://hf.co/papers/2506.05301 (Jun 5, 2026)
- **What changed:** One-step successor via adversarial post-training + adaptive window attention + feature matching loss. Dramatically faster inference than multi-step SeedVR at comparable or better quality.
- **Risk:** Low — one-step inference at ~same VRAM (~12–16 GB).
- **Action:** Locate SeedVR2 checkpoint on HF (or await ComfyUI-SeedVR node update). Update `build_seedvr2_video_upscale` model reference.

## Tier 2 — additive new builders (needs node-pack install)

New capabilities not yet wired into any spellcaster builder. Each requires ComfyUI node-pack installation on the local machine before wiring.

### 1. thedeoxen refcontrol LoRA suite → ControlNet conditioning for Klein workflows

- **Source:** https://hf.co/thedeoxen/refcontrol-FLUX.2-klein-9B-reference-pose-lora (Jun 22), plus canny / normal / lineart variants (all Jun 26)
- **Affects:** `build_klein_headswap`, `build_klein_repose`, `build_klein_face_detail`, `build_klein_detail`
- **What this adds:** OpenPose + reference-image conditioning (pose LoRA); canny edge, surface normal, and lineart structural conditioning — all currently absent from bare Klein workflows.
- **Action:** Install refcontrol LoRA into ComfyUI LoRA loader. Wire pose LoRA into `build_klein_repose` and `build_klein_headswap`; canny/normal into `build_klein_face_detail` and `build_klein_detail`. Add optional `controlnet_mode` parameter to these builders.

### 2. Klein 9B NV-FP4 / MX-FP8 quantizations → 9B on 16 GB without offloading

- **Source:** https://hf.co/dummy9996/flux.2-klein-9b-models-nvfp4-mxfp8 (Jun 26)
- **Affects:** All `build_klein_*` builders using the 9B variant
- **What this adds:** Klein 9B currently requires CPU offloading on 16 GB. NV-FP4 quant reduces to ~8–12 GB, removing the bottleneck and speeding up Klein workflows.
- **Action:** Test NV-FP4 checkpoint on RTX 5060 Ti. If fits, update the `klein_model_key` resolver to point to quantized checkpoint path as the new default.

### 3. SAM2Matting → alpha matting extension for `build_sam3_*` builders

- **Paper:** https://hf.co/papers/2606.27339 (Jun 25)
- **Affects:** `build_sam3_mask`, `build_sam3_extract`, `build_sam3_segment`, `build_magic_eraser`, `build_klein_sam3_inpaint`
- **What this adds:** Fine-grained alpha matte output (vs. binary masks) on the same prompt-driven SAM3 interface. Video temporal consistency built in.
- **Action:** Watch for ComfyUI-SAM2Matting node. When available, add optional `alpha_matting=True` branch to the SAM3 composite in `_composites.py`.

### 4. Real-VSR Dual-LoRA → temporal video upscale upgrade

- **Paper:** https://hf.co/papers/2506.15591 (Jun 18)
- **Affects:** `build_video_upscale`, `build_seedvr2_video_upscale`
- **What this adds:** One-step SD-based video SR with Consistency-LoRA + Detail-LoRA + Cross-Frame Retrieval. Better temporal consistency than frame-by-frame upscale.
- **Action:** Watch for HF checkpoint and ComfyUI node. Expected to become default video_upscale backbone.

### 5. SwiftVR → real-time alternative for video restoration

- **Paper:** https://hf.co/papers/2606.09516 (Jun 8)
- **Affects:** `build_seedvr2_video_upscale`, `build_wavespeed_upscale`
- **What this adds:** Real-time 4K video restoration via shifted-window attention + causal chunk processing. Explicitly designed for consumer-grade GPUs (≤16 GB).
- **Action:** Watch for HF checkpoint and ComfyUI node. Faster real-time alternative to SeedVR2 for the RTX 5060 Ti budget.

### 6. FLUX.1 Kontext (BFL) → potential new `build_kontext_edit` builder

- **Paper:** https://hf.co/papers/2506.15742
- **Affects:** `build_txt2img`, `build_img2img`, `build_style_transfer`, `build_generate_anything`
- **What this adds:** In-context image editing with strong character/object consistency. Already available on HF; widely adopted as backbone by the community (HairPort, Edit2Restore). Fits 16 GB at fp8/bnb.
- **Action:** Standard Flux ComfyUI node likely sufficient. Evaluate adding `build_kontext_edit` or updating `build_style_transfer` to accept a Kontext backbone option.
