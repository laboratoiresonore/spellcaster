## Tier 2 — additive new builders / substantial upgrades (needs node-pack install or weight swap)

### 1. PMRF blind face restoration → upgrade `build_face_restore` + `build_photo_restore`
- **Model**: `ohayonguy/PMRF_blind_face_image_restoration` — 230 M params, ICLR 2025, MIT license
- **HuggingFace**: https://hf.co/ohayonguy/PMRF_blind_face_image_restoration
- **ComfyUI node**: https://github.com/2kpr/ComfyUI-PMRF
- **VRAM**: 3.3 GB (vs CodeFormer ~8 GB at full res)
- **Why upgrade**: Posterior-mean rectified flow; lower VRAM, faster inference, better perceptual quality on moderately degraded faces. Avoids CodeFormer hallucination artifacts on soft textures.
- **Risk**: Low — model is 18+ months old, ComfyUI node stable.
- **Action**: Install ComfyUI-PMRF, replace CodeFormer node with PMRF in both builders. *Do NOT use the fsxedx/PMRF fork (Jul 27 upload, unverified account) — use the original ohayonguy repo.*

### 2. SeedVR2 native ComfyUI → simplify `build_seedvr2_video_upscale`
- **Change**: ComfyUI v0.28.0 (Jul 15, 2026) merged SeedVR2 into core.
- **Source**: https://docs.comfy.org/changelog
- **Why upgrade**: Builders can reference native SeedVR2 nodes without the third-party `ComfyUI-SeedVR2_VideoUpscaler` custom node.
- **VRAM**: 16 GB with blockswap — fits RTX 5060 Ti.
- **Risk**: Low.
- **Action**: After confirming local ComfyUI ≥ v0.28.0, update `build_seedvr2_video_upscale` to emit native node class names.

### 3. Krea 2 Turbo → augment `build_txt2img`, `build_img2img`, `build_generate_anything`
- **Model**: `Comfy-Org/Krea-2` — ~12 B params Turbo (8-step distilled), ComfyUI-native repo updated Jul 20
- **HuggingFace**: https://hf.co/Comfy-Org/Krea-2
- **VRAM**: FP8 Turbo ~12 GB — fits RTX 5060 Ti.
- **Arena rank**: Top-tier cluster (~1,150-1,185 Elo) alongside FLUX.2 and HiDream O1.
- **License**: Non-commercial (Krea AI model agreement). **Legal review required before production deployment.**
- **Risk**: Low (technically); Medium (license).
- **Action**: Add as an optional `arch: "krea2_turbo"` preset in the architecture registry. Do not enable as default until license reviewed.

### 4. HiDream O1 9B FP8 → augment `build_txt2img`, `build_img2img`, `build_generate_anything`
- **Model**: `Comfy-Org/HiDream-O1-Image` — 9 B unified image gen + editing, MIT license
- **HuggingFace**: https://hf.co/Comfy-Org/HiDream-O1-Image (updated May 28, 2026)
- **VRAM**: FP8 dev variant ~10 GB — comfortable on 16 GB.
- **Why notable**: MIT license at top-tier quality is the cleanest open-weight option available.
- **Risk**: Low.
- **Action**: Add as an optional `arch: "hidream_o1"` preset. ComfyUI native support already in place.

### 5. Wan-Dancer-14B → new `build_wan_dancer` builder
- **Model**: `Wan-AI/Wan-Dancer-14B` — 14 B params, Apache 2.0, released Jul 13, 2026
- **HuggingFace**: https://hf.co/Wan-AI/Wan-Dancer-14B
- **ComfyUI template**: https://docs.comfy.org/tutorials/video/wan/wan-dancer
- **What it does**: Portrait image + audio track → beat-synchronized dance video at 720p/30fps, up to ~1 min. Uses WanDancerEncodeAudio + WanDancerVideo nodes (ComfyUI Partner Nodes).
- **VRAM**: FP8/int8 quant fits 16 GB; Comfy-Org publishes FP8 repack weights.
- **Risk**: Medium — audio input handling not in any existing builder; niche use case; FP8 tight on 16 GB.
- **Action**: New builder needed (*cannot be wired locally until WanDancer nodes installed on the ComfyUI server*).

### 6. BFS-Best-Face-Swap LoRA update → augment `build_klein_headswap`
- **LoRA**: `Alissonerdx/BFS-Best-Face-Swap` — updated Jul 30, 2026 (567K downloads, 724 likes)
- **HuggingFace**: https://hf.co/Alissonerdx/BFS-Best-Face-Swap
- **VRAM**: Klein-9B ≈14-16 GB; Klein-4B ≈8-10 GB — RTX 5060 Ti handles both.
- **Why upgrade**: Jul 30 commit may include BFS Head V3 weights. BFS is the most-adopted Klein/Flux2 face-swap LoRA.
- **Risk**: Low.
- **Action**: Pull latest weights; diff commit log to confirm Head V3; update builder's default BFS LoRA path if confirmed.

### 7. ComfyUI-INT4-Fast → all Flux-based builders (speed/VRAM)
- **Node**: `viralvfx/ComfyUI-INT4-Fast` — updated Jul 10, 2026
- **Source**: https://github.com/viralvfx/ComfyUI-INT4-Fast
- **What it does**: On-the-fly INT4 (W4A4 convrot) quantization at load time; no pre-quantized checkpoint needed. Reduces effective VRAM use by ~50-60% vs FP16.
- **VRAM impact**: Cross-cutting benefit for ALL Flux-based builders (`build_klein_*`, `build_txt2img`, `build_img2img`, etc.)
- **Risk**: Low. **Verify RTX 5060 Ti (Blackwell) Tensor Core compatibility — node targets Ada/Ampere; Blackwell should be compatible but needs a test run.**
- **Action**: Install and test on a single builder (e.g., `build_txt2img` with Flux preset) before deploying cross-builder.

### 8. GLM-Image 7B → augment `build_style_transfer`
- **Model**: `zai-org/GLM-Image` — 7 B params, MIT license, January 2026
- **HuggingFace**: https://hf.co/zai-org/GLM-Image
- **VRAM**: FP8 ~16 GB (tight); FP16 ~30 GB (exceeds budget).
- **Unique feature**: 4-reference image style transfer — no other open-weight model has this at comparable quality.
- **Risk**: Medium — less community testing than Flux/Krea; FP8 at the VRAM ceiling.
- **Action**: Evaluate FP8 variant for `build_style_transfer` as an alternative path when multi-reference style is needed.
