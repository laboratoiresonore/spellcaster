## Tier 1 — Drop-in supersessions (ship soon)

These replace an existing backbone with no new node-pack install (only a different checkpoint file or existing node-pack update).

### 1. HyperSwap 1c_256.onnx → `build_faceswap` / `build_faceswap_model`

**What changed:** HuggingFace mirror of FaceFusion's HyperSwap 256 ONNX trio uploaded Jul 29. The model itself originates from facefusion/models-3.3.0 (Jun 2025) but was not previously surfaced in Spellcaster's dependency list. ComfyUI-ReActor ≥0.6.2 already supports it — place `hyperswap_1c_256.onnx` in `ComfyUI/models/hyperswap` and select in the ReActor node.

**Why it matters:** Operates at 256×256 (double inswapper's 128×128), same InsightFace ArcFace pipeline, visibly sharper eyes and skin detail. ~2 GB VRAM — identical to current.

**Action:** Swap `inswapper_128.onnx` default for `hyperswap_1c_256.onnx` in the ReActor node configuration.

Source: https://huggingface.co/prstyaDev/FaceFusion-Face-Swap-Hyperswap

---

### 2. Lucida checkpoint → `build_rembg_birefnet`

**What changed:** `egeorcun/lucida` uploaded Jul 24 — a BiRefNet-HR fine-tune targeting transparent objects, glass, VFX glow, and illustrations where RMBG-2.0 fails (MAE 0.0257 vs 0.0401). ComfyUI-RMBG v3.1.0 (Jul 21) adds Lucida to its model selector and a new alpha-threshold sensitivity parameter.

**Action:** Update ComfyUI-RMBG to v3.1.0 and expose Lucida as a named variant in `build_rembg_birefnet`. Keep RMBG-2.0 as default (it still leads on hair segmentation); route glass/glow use-cases to Lucida.

Source: https://huggingface.co/egeorcun/lucida · https://github.com/1038lab/ComfyUI-RMBG

---

### 3. SAM 3.1 checkpoints → `build_sam3_segment`, `build_sam3_mask`, `build_sam3_extract`

**What changed:** SAM 3.1 released Mar 27 2026 by Meta. Introduces Object Multiplex — shared-memory joint multi-object tracking in a single forward pass, ~2× video throughput with no accuracy loss. 848M params, same API surface as SAM 3.

**Blocker:** HuggingFace access is gated (Meta approval required). Request access at facebookresearch/sam3.

**Action:** Once HF access is approved, swap SAM 3 checkpoint paths to SAM 3.1 — no code changes to the builders required.

Source: https://github.com/facebookresearch/sam3

---

### 4. Depth Anything 3 → `build_depth_map_v3`

**What changed:** DA3 (ByteDance-Seed, Nov 2025) extends DepthAnythingV2 with multi-view consistency, monocular metric depth (DA3Metric-Large), pose estimation, and 3D Gaussian output. ComfyUI-DepthAnythingV3 wrapper listed in official DA3 Awesome Projects. DA3-Streaming confirmed under 12 GB VRAM for ultra-long video.

**Action:** Install ComfyUI-DepthAnythingV3; update `build_depth_map_v3` model path to DA3-Large (~8 GB VRAM).

Source: https://github.com/ByteDance-Seed/depth-anything-3

---

### 5. LTX-2.3 checkpoint → `build_ltx_video`

**What changed:** Lightricks/LTX-2.3 (22B, last updated Jul 9, 9.9M downloads, 1738 likes) is now the dominant LTX backbone. If Spellcaster's `build_ltx_video` is still routed through the original 8B LTX-Video, this is an overdue upgrade. Spatial and temporal upscalers are built in to LTX-2.3, partially overlapping `build_video_upscale`.

**Note:** LTX-2.3 update itself predates the 7-day window but was not tracked in any prior Spellcaster research file — treating as a first-run finding.

**Action:** Verify current LTX checkpoint in `build_ltx_video`. If on 8B base, migrate to `Lightricks/LTX-2.3` with sequential offload on 16 GB.

Source: https://huggingface.co/Lightricks/LTX-2.3

## Tier 2 — Additive new builders (needs node-pack install or new method)

### 1. Microsoft Mage-Flow 4B → new `build_mageflow_txt2img` + `build_mageflow_edit`

MIT licensed. GenEval 0.90 — highest among all open-source T2I models, beating FLUX.2 (0.87) and Qwen-Image (0.87). Ships as Base, RL, and Turbo (4-step). Companion Mage-Flow-Edit and Mage-Flow-Edit-Turbo accept image + text instruction (competitor to `build_qwen_edit`). Native ComfyUI support in v0.29.0 (Jul 29). Text encoder: Qwen3-VL 4B. Use int8_convrot variants for 16 GB headroom (~9 GB peak).

Source: https://huggingface.co/Comfy-Org/Mage-Flow

---

### 2. JoyAI-Image-Edit-Plus → new `build_joyai_edit`

JD.com Apache 2.0 open-source. 8B MLLM + 16B MMDiT (~24B total). Unique capability: 1–6 reference images alongside text instruction for multi-reference synthesis. Native ComfyUI in v0.29.0 (Jul 29). INT8 path is ~16 GB (tight). Recommend GGUF Q4_K_M for safe 16 GB budget.

Source: https://huggingface.co/jdopensource/JoyAI-Image-Edit-Plus-ComfyUI

---

### 3. NVIDIA PiD v1.5 → optional VAE path for all Flux/Klein builders

Drop-in VAE decoder replacement: reformulates latent→pixel decode as a single-step conditional pixel diffusion pass, producing 2K/4K output. v1.5 (Jul 9) fixes color fidelity and corner artifacts. Supported models: FLUX.1, FLUX.2, Qwen-Image. Two ComfyUI node packs available. Overhead: ~2–3 GB VRAM during decode only (not held during sampling).

Source: https://huggingface.co/nvidia/PiD

---

### 4. Krea 2 Identity Edit LoRA v1.2 → new `build_krea_identity`

Instruction-based identity-preserving editing LoRA for Krea-2-Raw. Updated Jul 29. Enables face/head/eye swap via plain-text instructions using diffusion inpainting; natural boundary blending but softer likeness than ReActor. FP8 at ~12 GB VRAM. ComfyUI node: lbouaraba/comfyui-krea2edit. **License: non-commercial only** — confirm with user before wiring.

Source: https://huggingface.co/conradlocke/krea2-identity-edit

---

### 5. PMRF Blind Face Restoration → additive fast path in `build_face_restore`

ICLR 2025 paper. 230.5M params, 3.3 GB VRAM, ~1 s/image. MIT. ComfyUI-PMRF node (2kpr/ComfyUI-PMRF) exists. Does not replace CodeFormer's fidelity-dial workflow; use as fast low-degradation first pass or fallback.

Source: https://huggingface.co/fsxedx/PMRF_blind_face_image_restoration

API partner node live in ComfyUI v0.29.2. Open weights "coming within days" per MiniMax — not yet on HF. Monitor; do not wire until weights ship and VRAM confirmed ≤16 GB.
