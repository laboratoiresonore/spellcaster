## Tier 1 — drop-in supersessions (ship soon)

No new node-pack installs required — new checkpoint names or updated builder parameters only.

### 1a. Lucida → `build_rembg_birefnet`

**What:** `egeorcun/lucida` is a BiRefNet_HR fine-tune (~885 MB, MIT). The
`lucida.safetensors` checkpoint landed in the Comfy-Org/BiRefNet model
collection on approximately July 26–28 (confirmed "7 days ago" as of Aug 2).
It targets edge cases where BiRefNet-general degrades: semi-transparent glass,
camouflage, VFX glow/emissive effects, and line-art with soft shadows.
Already surfaced by ComfyUI-RMBG v3.1.0.

**Action:** Add `"lucida"` as a selectable checkpoint in `build_rembg_birefnet`
alongside `"BiRefNet-general"`. No pipeline changes.

**Confidence:** 0.88 · **Risk:** low

---

### 1b. JoyAI-Image-Edit-Plus → `build_qwen_edit` (quality path)

**What:** `jdopensource/JoyAI-Image-Edit-Plus-ComfyUI` (Apache 2.0) is a
Qwen3-VL 8B MLLM fused with a 16B MMDiT for instruction-guided single-image
editing. Key advantages over the current Qwen Image Edit 2509 backbone:
- Supports up to 3 reference images
- Substantially better face/identity preservation (avoids face drift)
- INT8 format: ~16 GB active VRAM — feasible on RTX 5060 Ti
- 6.3 K downloads on GGUF quant in 2 weeks; `Comfy-Org/JoyAI-Image-Edit`
  official wrapper created July 20; native support shipped in v0.29.0 (Jul 29)

**Action:** Add `"joyai_edit_plus"` as a backend option in `build_qwen_edit`,
loading via the `Comfy-Org/JoyAI-Image-Edit` nodes. Test INT8 checkpoint on
RTX 5060 Ti before declaring production-ready.

**Confidence:** 0.88 · **Risk:** low (INT8 path); medium (need VRAM test)

---

### 1c. Mage-Flow-Edit-Turbo → `build_qwen_edit` (speed path)

**What:** `microsoft/Mage-Flow-Edit-Turbo` (MIT) is a 4-step distilled
instruction editor from the same family as Mage-Flow T2I. FP16 peak is 18–20
GB (too large for 16 GB), but **NVFP4 quant** (for NVIDIA Blackwell/RTX 50xx,
which includes the RTX 5060 Ti) brings active VRAM to ~2.2 GB. Community
NVFP4 at `ajh-code/Mage-Flow-Edit-Turbo-XPO3-NVFP4` (Jul 30, 523 downloads).
Also FP8 quant at `rootlocalghost/Mage-Flow-Edit-Turbo` (Jul 30) for
non-Blackwell fallback.

**Action:** Same builder as 1b — add `"mageflow_edit_turbo"` as a third
option routing through ComfyUI's native MageFlow nodes (v0.29.0, CORE-372).

**Confidence:** 0.90 · **Risk:** low (NVFP4 on RTX 5060 Ti confirmed)

---

### 1d. LTX 2.3 IC-LoRA / ID-LoRA → `build_ltx_video`

**What:** ComfyUI v0.29.0 (Jul 29) fixed IC-LoRA model detection for LTX-Video.
LTX-2.3 ships two LoRA-based control modes not yet exposed in spellcaster:
- **IC-LoRA** — transfers motion+structure from a reference video (V2V style)
- **ID-LoRA** — identity-preserving video generation from a face reference

**Action:** Add optional `ic_lora_filename`, `id_lora_filename`, and
`ic_strength` kwargs to `build_ltx_video`. Route through existing
`LTXVApplySTG` + `LTXAVTextEncoderLoader` nodes per docs.comfy.org/tutorials/video/ltx/ltx-2-3.

**Confidence:** 0.80 · **Risk:** low

---

### 1e. SeedVR2 v2.5 / native → `build_seedv2r`

**What:** ComfyUI v0.28.0 (Jul 15) added native SeedVR2 nodes. SeedVR2 v2.5
adds flicker-free batch processing (minimum batch=5 for temporal consistency).
If the current builder routes through the third-party custom node, migrating
to native reduces maintenance overhead.

**Action:** Audit `build_seedv2r` — if it uses `ComfyUI-SeedVR2_VideoUpscaler`,
replace with native v0.28.0 node paths.

**Confidence:** 0.80 · **Risk:** low

## Tier 2 — additive new builders (needs node-pack install)

All natively supported in ComfyUI v0.29.0 — no additional custom node installs.

### 2a. `build_mageflow_txt2img` — Microsoft Mage-Flow T2I

**What:** Mage-Flow (Microsoft, MIT, announced Jul 22, ComfyUI native Jul 29)
is a 4B DiT for text-to-image at native resolution up to 2048px.

- **GenEval score:** 0.90 — highest open-source, above FLUX.2 (0.87) and
  Qwen-Image (0.87)
- **VRAM:** ~9 GB FP16; NVFP4 quant ~2.2 GB for RTX 50xx Blackwell (RTX 5060 Ti)
- **License:** MIT (commercial-friendly)
- **Comfy-Org repackage:** 75 K downloads in < 2 weeks
- **Variants:** Base, RL-aligned, 4-step Turbo (0.59 s/image on A100)
- **arXiv:** 2607.19064

**Spellcaster mapping:** New `build_mageflow_txt2img` builder with
`mageflow` architecture key in `load_model_stack`. Dispatch: `MageFlowLoader`
(native v0.29.0 node). Turbo variant should be the default preset.

**Confidence:** 0.95 · **Risk:** low

---

### 2b. `build_mageflow_edit` — Mage-Flow-Edit instruction editing

**What:** Mage-Flow-Edit and Mage-Flow-Edit-Turbo share the Mage-Flow
4B transformer but are fine-tuned for instruction-based image editing.
Already covered in Tier 1 (1c) as an upgrade to `build_qwen_edit`.
If the decision is to keep `build_qwen_edit` separate, a standalone
`build_mageflow_edit` builder is the alternative approach.

**Confidence:** 0.90 · **Risk:** low

---

### 2c. `build_wan_video_uni3c` — Uni3C camera ControlNet for Wan

**What:** Uni3C (CORE-365, native v0.29.0) adds camera-trajectory control
to all Wan model variants by extracting motion from a reference video.

- **Weights:** `Kijai/WanVideo_comfy`:
  `Wan21_Uni3C_controlnet_fp16.safetensors` and
  `Wan22_Uni3C_controlnet_fp16.safetensors`
- **Node:** `WanVideoUni3C_ControlnetLoader` (native v0.29.0)
- **VRAM:** Minimum 24 GB recommended; 16 GB marginal with block-swap or
  GGUF Q4. Classify RTX 5060 Ti as **feasible with caveats**.

**Spellcaster mapping:** New `build_wan_video_uni3c` builder, or add optional
`uni3c_ref_video` kwarg to existing `build_wan_video` / `build_wan22_t2v`.

**Confidence:** 0.85 · **Risk:** medium (VRAM at 16 GB)

## Tier 3 — monitor / not wire-ready

### 3a. MiniMax H3 — 2K video + native audio (weights due ~Aug 3–7)
- Launched Jul 31 as API. Generates 2K clips with natively synced audio, 15 s.
  Benchmarks above Seedance 2.0. Open-source weights announced; ComfyUI v0.29.2
  added API support. As of Aug 2, no public checkpoint exists.
  Will need `build_minimax_h3_video` once weights + VRAM specs confirmed.
- **URL:** https://www.scmp.com/tech/article/3362540

### 3b. FLUX 3 — Black Forest Labs (no weights)
- Announced Jul 23. Multimodal frontier (image + up to 20 s video + audio).
  Image variant described as superior to FLUX.2 on complex prompts and
  multilingual text. Open-weight "FLUX 3 Dev" planned for Q4 2026 per BFL.
  No local weights, no ComfyUI support as of Aug 2.
  Watch: https://huggingface.co/black-forest-labs
- **Risk:** high planning risk (timeline uncertain)

### 3c. JoyAI-Image-Edit (standard, not Plus)
- `jdopensource/JoyAI-Image-Edit-ComfyUI` updated Jul 28. Standard (non-Plus)
  version has higher VRAM requirements (32.5 GB bf16 transformer). With NF4
  quant ~13 GB — marginal. Plus version (Tier 1b) is better choice at 16 GB.

### 3d. Hunyuan3D 3.1 / PolyGen (cloud API only)
- Substantially better mesh/texture quality than open-source 2.1. Requires
  Tencent Cloud API. Not self-hostable. Watch for open-source ETA on
  tencent-hunyuan/Hunyuan3D-2.1 GitHub issue tracker.

### 3e. Anima LLLite — new control architecture
- Lightweight ControlNet for Anima DiT (anime-focused model). Native v0.29.0.
  Not relevant to spellcaster unless Anima becomes a target backbone.
  Monitor if Klein/Flux2 equivalents emerge.
- **URL:** https://huggingface.co/kohya-ss/Anima-LLLite

### 3f. Krea 2 Style Reference LoRA → `build_style_transfer`
- `ostris/krea2_turbo_style_reference` (Jul 8, native ComfyUI v0.29.0).
  New paradigm for style transfer using Krea 2 Turbo as backbone.
  Krea 2 Turbo FP8 ≈ 13 GB — tight on 16 GB RTX 5060 Ti. Non-commercial
  Krea license. Potential upgrade over IPAdapter SDXL but license and VRAM
  constraints push to Tier 3 pending hardware test.
- **URL:** https://huggingface.co/ostris/krea2_turbo_style_reference

### 3g. Wan-Dancer-14B (released Jul 13 — borderline)
- Music-driven long-duration dance video (Apache 2.0). ComfyUI native tutorial
  at docs.comfy.org/tutorials/video/wan/wan-dancer. INT8/INT4 convrot quant
  (`Winnougan/Wan-Dancer-14B-INT8-INT4-Convrot`) makes 16 GB feasible.
  No spellcaster builder exists. Consider `build_wan_dancer_video` in next sprint.
- **URL:** https://huggingface.co/Wan-AI/Wan-Dancer-14B

### 3h. FeyNoBg (released Jul 21 — near-miss)
- 263M-param BiRefNet-based SOTA on 4 benchmarks. Currently a HF Space + Python
  library only — no loadable safetensors or ComfyUI node. Monitor `feyninc`.
- **URL:** https://huggingface.co/spaces/feyninc/feynobg

### 3i. ID-V2V (Eyeline-Labs)
- Identity-preserving video restyling. Wan 2.1 + VACE, 8× A100 required.
  ~96 GB checkpoint. Not viable at 16 GB. 12–18 month horizon.
