## Tier 1 — Drop-in supersessions (ship soon)

These require only a model-file or checkpoint swap. No new ComfyUI node packs needed beyond what
is already in the stack, and licensing is permissive.

### 1. HyperSwap 1c_256 ONNX → `build_faceswap`, `build_faceswap_model`

The `inswapper_128.onnx` in the current stack generates 128×128 face tiles. HyperSwap 1c_256 from
FaceFusion 3.3.0 operates at 256×256 — a 4× pixel-count improvement with no degradation in swap
fidelity. The 1a variant is speed-optimized; 1c is quality-optimized. All three (1a/1b/1c) are
bundled under `facefusion/models-3.3.0` (HuggingFace) with the same ONNX runtime interface.

ComfyUI-ReActor v0.6.2 (April 25, 2026) added native HyperSwap 1a/1b/1c support plus a new
"Restore Face Advanced" node that applies restoration only to the swapped face region, reducing
over-restoration artifacts on background. The node configuration change is minimal:
`swap_model="hyperswap_1c_256.onnx"`.

- **Action:** Swap default model string in `build_faceswap` and `build_faceswap_model`; update
  ReActor node class_type if needed.
- **License:** FaceFusion open license.
- **Risk:** Low. 1:1 ONNX interface; VRAM delta negligible.

### 2. SAM 3.1 → `build_sam3_segment`, `build_sam3_mask`, `build_sam3_extract`

SAM 3.1 (Meta AI, March 27, 2026) adds shared-memory multi-object multiplexing on top of SAM 3.
The API shape is unchanged — same checkpoint interface, same input/output contract. Speed gains are
substantial: 2× throughput for 16-object scenes, 7× for 128+ objects. Weights are available via
gated HuggingFace access (Apache 2.0) at `facebookresearch/sam3`. The existing SAM3 ComfyUI node
pack (e.g., ComfyUI-Impact-Pack, ComfyUI-RMBG by 1038lab) should accept the 3.1 checkpoint
directly — verify config key `sam3_checkpoint` accepts the new filename.

- **Action:** Download SAM 3.1 checkpoint; update default path in `build_sam3_*` methods.
- **Risk:** Low. Confirm checkpoint load in node before swapping default.

### 3. Boogu-Image-0.1-Edit-Turbo → `build_qwen_edit` *(IN WINDOW — Jul 8, 2026)*

Apache 2.0 10B unified generation+editing model. The Edit-Turbo variant in the July 8 release fixes
severe image quality degradation and poor object-removal performance that shipped in the prior
Edit-Turbo. Covers instruction-guided edits (add, remove, reposition, style transfer, bilingual text
rewriting). BF16/FP8/NVFP4/INT8 quantized weights are available at `Comfy-Org/Boogu-Image`
(repackaged weights), with native ComfyUI support via `TextEncodeBooguEdit` node
(`ComfyUI-Boogu`). Tutorial at docs.comfy.org/tutorials/image/boogu/boogu-image-0.1.

- **Action:** Benchmark Boogu Edit-Turbo vs current Qwen Edit on standard editing test set.
  If quality ≥ parity, add as default or fallback in `build_qwen_edit`.
- **License:** Apache 2.0.
- **Risk:** Low. ComfyUI-native, well-documented.

## Tier 2 — Additive new builders (needs node-pack install)

These represent new capabilities or substantial quality jumps that require installing a new ComfyUI
custom node pack or significant workflow restructuring.

### 4. LTX-2.3 (22B, FP8) → `build_ltx_video`

LTX-2.3 from Lightricks (released March 5, 2026; HF repo touched July 9) is a generation-jump from
the LTX-Video 0.9.x currently wired in `build_ltx_video`. Key gains:
- 22B parameters vs ~5B in LTX-Video 0.9.x
- Native 4K at up to 50 fps, clips to 20 seconds
- Synchronized stereo audio in a single inference pass
- 8-step distilled variant (CFG=1) for practical 16 GB inference
- FP8 checkpoint (`Lightricks/LTX-2.3-fp8`) designed for Ada/Blackwell hardware

The FP8 variant runs on RTX 5060 Ti 16 GB. Native ComfyUI support was added June 2026 with
workflow templates. The IC-LoRA ecosystem offers multiple additive capabilities:
`LTX-2.3-22b-IC-LoRA-LipDub` (lip sync), `IC-LoRA-HDR` (SDR→HDR), `IC-LoRA-Colorization`
(grayscale→color), `IC-LoRA-In-Outpainting`, `IC-LoRA-Ingredients` (character consistency from
reference sheet), `IC-LoRA-Decompression` (compression artifact removal).

- **Action:** Replace `build_ltx_video` backbone with LTX-2.3 FP8. Consider adding
  `build_ltx_lipdub` and `build_ltx_colorize` as thin wrappers over the IC-LoRA variants.
- **Node pack:** Native ComfyUI (via Lightricks integration, June 2026).
- **Risk:** Medium. Significant version delta; test all existing workflow invocations.

### 5. Pixal3D → `build_hunyuan_3d_mesh`, `build_hunyuan_3d_textured`

TencentARC Pixal3D (SIGGRAPH 2026, released ~May 2026) uses pixel-aligned feature back-projection
into 3D Gaussians on top of TRELLIS.2, producing near-reconstruction-level fidelity GLB meshes
with PBR textures. Competes directly with Hunyuan3D-2.x in the same task domain (image-to-3D).

VRAM options:
- Standard: ~24 GB model files on disk; runs at 16 GB VRAM limit (tight, 1536 → 1024 resolution)
- GGUF quantized: ~6 GB VRAM — comfortably within budget, slight quality drop at extreme detail

Two ComfyUI node packs available: `dreamrec/ComfyUI-Pixal3D` and `Saganaki22/Pixal3D-ComfyUI`.
License is MIT.

- **Action:** Install `ComfyUI-Pixal3D`; wire `build_hunyuan_3d_mesh` / `build_hunyuan_3d_textured`
  to use Pixal3D GGUF as the new default (quality validation needed vs Hunyuan3D).
- **Risk:** Medium. Output format is GLB+PBR textures (same as Hunyuan3D output contract).
  Confirm downstream GLB consumers accept Pixal3D output without changes.

### 6. DreamID-V → `build_faceswap_mtb` (video face swap)

ByteDance DreamID-V (ECCV 2026, January 2026, Apache 2.0) does video face swapping via a Diffusion
Transformer backbone (Wan2.1-T2V-1.3B). The "Faster" variant is explicitly tuned for 16 GB VRAM
cards. Two mature ComfyUI nodes exist:
- `HM-RunningHub/ComfyUI_RH_DreamID-V`
- `Goldlionren/ComfyUI_JR_DreamID-V`

MTB's current approach to video face swap is frame-by-frame (no temporal consistency); DreamID-V
conditions on video tokens across time, producing temporally coherent swaps.

- **Dependency:** Wan2.1-T2V-1.3B weights + DWPose ONNX models required.
- **Action:** Add `build_dreamidv_faceswap` builder; present alongside `build_faceswap_mtb`
  for video targets.
- **Risk:** Medium. New dependency chain (Wan2.1 1.3B); test for temporal consistency vs MTB.

485K HF downloads, MIT license. LoRA for Klein 4B/9B for high-fidelity face and head swaps in
still images (multiple "tier" checkpoints from subtle face swap to full head transfer). The Klein
4B variant fits comfortably within 16 GB. ⚠️ Klein 9B variant exceeds 16 GB — do not use as default.

- **Action:** Add Klein 4B BFS LoRA path to `build_faceswap` for cases where Flux2/Klein is
  already loaded; use as quality fallback over inswapper for still images.
- **Risk:** Low. MIT license, extensive community validation.

### 8. FlashVSR v1.1 → complement `build_wavespeed_upscale`, `build_video_upscale`

CVPR 2026 one-step diffusion streaming video super-resolution. ~17 fps for 768×1408 on A100; ~12×
faster than prior one-step VSR methods. ComfyUI node: `1038lab/ComfyUI-FlashVSR`.
FlashVSR wins on throughput; SeedVR2 wins on peak fidelity. The two are complementary — FlashVSR
for real-time/fast preview paths, SeedVR2 for final export.

- **Action:** Install `ComfyUI-FlashVSR`; add `build_flashvsr_upscale` as a speed-tier alternative
  in the upscale menu.
- **Risk:** Low. 16 GB should be sufficient (conditional decoder is lightweight).

### 9. IConFace (FLUX.2-Klein 4B) → `build_face_restore`

IConFace (arXiv 2605.02814, May 2026) replaces CodeFormer/GFPGAN with a FLUX.2-Klein-base-4B
backbone for blind face restoration. Supports both no-reference (single degraded portrait) and
reference-aware (1–3 same-identity reference images) modes in one checkpoint. Default: 512 res,
12 steps, guidance 4.0.

Klein 4B VRAM footprint: ~10–14 GB, within 16 GB budget.

ComfyUI node: `cosmicrealm/ComfyUI-Flux-FaceIR`. Weights: `zhangjinyang/flux-restoration` on HF.

- **Caveat:** Inference-only release (training code not yet public); limited community validation.
- **Action:** Evaluate `ComfyUI-Flux-FaceIR` against CodeFormer on the standard face restoration
  test set before promoting to default. Add as high-quality opt-in initially.
- **Risk:** Medium (node maturity unknown; confidence 0.72).
