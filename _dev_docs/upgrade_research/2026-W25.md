## Tier 1 — drop-in supersessions (ship soon)

These are wire-ready replacements for existing builders. The underlying ComfyUI node or checkpoint exists, fits within the 16 GB VRAM budget, and represents a clear quality or capability improvement.

### 1. LTX-2.3 → `build_ltx_video`
**Source:** https://hf.co/Lightricks/LTX-2.3 | **License:** other (Lightricks) | **Released:** March 5, 2026

LTX-2.3 is a 22B-parameter multimodal video model, a generation jump above the ~13B LTX-Video currently wired. Key gains:
- Native 4K at 50 fps (vs 720p/30fps)
- Synchronized stereo audio in a single diffusion pass (no post-audio layering)
- Portrait 9:16 social format
- Built-in spatial + temporal upscaler
- IC-LoRA ecosystem: HDR, LipDub, Motion-Track-Control, Union-Control

VRAM note: standard 22B FP16 needs ~21 GB. Confirmed 16 GB-compatible paths exist:
- GGUF quantized (`fwwrsd/lightricks-ltx-2-3-fp8`, May 19, 2026)
- 1-step distilled variant (~14 GB peak per community testing)

ComfyUI support since v0.16, new nodes: `LTXAudioVideoLoader`, `LTXAudioConditioner`, `LTXVideoSampler`.

**Action:** Replace `Lightricks/LTX-Video` backbone in `build_ltx_video` with `Lightricks/LTX-2.3`. Add GGUF quantization path. Audio conditioning is optional/additive.

### 2. SAM 3.1 Object Multiplex → `build_sam3_segment`, `build_sam3_mask`, `build_sam3_extract`, `build_klein_sam3_inpaint`
**Source:** https://github.com/Comfy-Org/ComfyUI/pull/13408 | **License:** Meta (gated) | **Released:** March 27, 2026 (ComfyUI support ~April 2026)

SAM 3.1 introduces Object Multiplex mode: shared-memory multi-object tracking in a single forward pass. Up to 7× faster than SAM 3.0 for multi-subject scenes. Checkpoint: `sam3.1_multiplex_fp16`.

Native ComfyUI docs: https://docs.comfy.org/tutorials/utility/video-segment-sam3

**Action:** The existing `SAM3Segment` node in spellcaster should be tested with the `sam3.1_multiplex_fp16` checkpoint — likely a config change only, no workflow rewrite required.

### 3. ReActor v0.6.2 + HyperSwap 256px → `build_faceswap`
**Source:** https://github.com/Gourieff/ComfyUI-ReActor | **License:** AGPL-3.0 | **Released:** April 25, 2026

HyperSwap models (`hyperswap_1a/1b/1c_256.onnx`, 256 px) are higher-resolution successors to `inswapper_128.onnx` (128 px). Available through FaceFusion Labs / FaceFusion v3.6.1. ReActor v0.6.2 added native support.

Additionally, a `Restore Face Advanced` node now accepts a face restore filter for per-swap enhancement.

Note: ReActor v0.7.0 alpha is in development and will drop InsightFace/C++ build dependency entirely.

**Action:** Swap `inswapper_128.onnx` for `hyperswap_1c_256.onnx` in `build_faceswap`. Update node if needed.

## Tier 2 — additive new builders (needs node-pack install)

These require a new custom node pack and/or model download on the local ComfyUI instance before they can be wired.

### 4. SCAIL-2 → new `build_scail2_animate` ✦WITHIN WINDOW (June 9-13, 2026)
**Source:** https://github.com/zai-org/SCAIL-2 | **License:** Apache 2.0 | **Released:** June 9, 2026 (CVPR 2026 Findings)

SCAIL-2 is a skeleton-free, end-to-end character animation / motion-transfer model built on Wan 2.1 14B. It takes a reference character image + a driving video and transfers motion without skeleton extraction, OpenPose overlays, or ControlNet.

Capabilities: single character, cross-identity replacement, multi-character scenes, animals, zero-shot SAM3D mesh rendering.

Requires: SCAIL-2 weights + preprocessor node. ComfyUI workflows available at nextdiffusion.ai and runcomfy.com.

VRAM: built on Wan 2.1 14B — same as `build_wan_animate_video`. With block-swap fits ~16 GB (same approach as WAN block-swap builders).

### 5. Ideogram 4.0 → new `build_ideogram4_txt2img`
**Source:** https://hf.co/ideogram-ai/ideogram-4-fp8 | **License:** other (non-commercial weights) | **Released:** June 3, 2026

Ideogram 4 is a 9.3B DiT with Qwen3-VL-8B-Instruct + Gemma4 text encoders. Best-in-class multilingual text rendering, structured JSON prompting, bounding-box layout control, hex color palette constraints. Uses FLUX.2 VAE.

Day-0 ComfyUI v0.24.0 support. New nodes: `Ideogram4Scheduler`, `DualModelGuider`, `CFGOverride`.

Note: non-commercial license — does not replace Klein family for NSFW or commercial workflows.

---

### 6. Microsoft Lens → augments `build_txt2img`
**Source:** https://hf.co/microsoft/Lens + https://hf.co/microsoft/Lens-Turbo | **License:** MIT | **Released:** May 22, 2026

Lens is a 3.8B dual-stream MMDiT with GPT-OSS-20B MoE text encoder. Native 1440×1440. Lens-Turbo: 4-step generation at ~0.84s per 1024×1024. MIT license = commercial-ready.

ComfyUI integration: PR #14077 (kijai) merged ~June 2026. Weights via `Comfy-Org/Lens`.

Recommended as a fast, high-quality alternative to FLUX.1-schnell for time-sensitive workflows or batch operations.

---

### 7. FLUX.1 Kontext-dev → new `build_flux_kontext_img2img`
**Source:** https://hf.co/black-forest-labs/FLUX.1-Kontext-dev | **License:** other (BFL research) | **Released:** Jan 1, 2026 (paper: June 2025)

FLUX.1 Kontext unifies image generation and context-aware editing in a 12B flow-matching model. Capabilities: local editing (object/attribute changes), global style transfer, character reference consistency, text editing (glyphs), multi-turn edit chains.

Native ComfyUI docs: https://docs.comfy.org/tutorials/flux/flux-1-kontext-dev

Key use cases for spellcaster: augments `build_img2img` with coherent multi-reference editing, could replace some `build_style_transfer` and `build_inpaint` paths.

### 8. ComfyUI-Flux-FaceIR → new `build_flux_face_restore`
**Source:** https://github.com/cosmicrealm/ComfyUI-Flux-FaceIR | **License:** unspecified | **Active:** April-June 2026

Uses Klein 4B as face restoration backbone with RetinaFace detection. Supports blind restoration (no reference) and reference-guided restoration (up to 3 refs). Significant quality uplift over CodeFormer for photorealistic cases.

Requires Klein 4B + qwen_3_4b CLIP + flux2-vae — all already on local machine per Klein family support.

Tencent's third-generation 3D generation model, available via ComfyUI Partner Nodes. Direct incremental upgrade over Hunyuan3D 2.x that spellcaster currently uses. Model quality improvements in geometry and texture fidelity.

### 10. TripoSplat → new `build_triposplat_3d`
**Source:** https://hf.co/VAST-AI/TripoSplat | **License:** MIT | **Released:** ~June 1, 2026

Image-to-3D Gaussian Splat model from VAST-AI. Day-0 native ComfyUI v0.23.0 support. Single image → up to 262,144 Gaussians using DeG adaptive detail allocation. Outputs `.splat` format (complementary to mesh — different use case).

Minimal codebase, MIT license, no diffusers/transformers dependency.

### 11. RealRestorer → new `build_realrestorer`
**Source:** https://github.com/StartHua/Comfyui_RealRestorer + https://hf.co/RealRestorer/RealRestorer | **Released:** April 2026

Handles 9 real-world degradations (blur, rain, reflection, low-light, noise, haze, moire, flare, artifacts) in a single model. ComfyUI node already packaged. Complementary to SUPIR — lighter-weight universal restoration without the 5-stage SDXL pipeline.
